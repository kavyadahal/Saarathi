How these models
actually learn

Every model on this page does the same four things in a loop: guess, measure how wrong, work out which direction is less wrong, take a small step that way. What changes between them is only how they guess and how they measure wrong. Everything below is worked with real numbers you can check by hand.

00

The shared skeleton

Before any specific model, learn this loop. Linear regression, logistic regression, and neural networks all run it. Decision trees are the one exception — they build themselves differently, and we'll flag exactly where they diverge.

One trip around this loop is called an epoch (or an iteration). Training is just doing it hundreds or thousands of times.

The vocabulary, once, so it never confuses you again

termwhat it really means
forward passRun the data through the current formula to get predictions. "Forward" = data flows in the input→output direction.
lossOne number summarising how wrong all the predictions are. Lower is better. Also called cost or error.
gradientFor each parameter, the answer to: "if I nudge this up by a tiny bit, does the loss go up or down, and how fast?" A slope.
backpropagationThe procedure for computing those gradients, working backwards from the loss to each parameter using the chain rule.
learning rate (lr)How big a step to take. Too small = crawls. Too big = overshoots and never settles.
gradient descentThe whole strategy: repeatedly step each parameter downhill on the loss.
epochOne full pass over the training data.
Why "descent" and why minus. The gradient points in the direction that makes loss increase. You want the opposite, so the update always subtracts: w ← w − lr × dw. That minus sign is the entire reason the model gets better rather than worse.

Linear regression

Use it when the thing you're predicting is a number on a continuous scale — house price, exam score, disease progression. It fits a straight line through the points.

Step 1 — the model formula (the guess)

A straight line has exactly two dials:

ŷ = w · x + b

w (weight/slope) controls how steeply the line rises. b (bias/intercept) slides the whole line up or down. Training = finding good values for these two numbers, and nothing else.

Step 2 — forward pass with starting values w = 0, b = 0

We always start from a dumb guess. With both dials at zero, every prediction collapses to zero:

xw·x + bŷ (predicted)y (true)error = ŷ − y

A negative error means we predicted too low. All five are negative, so the line needs to come up — steeply.

Step 3 — the loss: mean squared error

Why square the errors? Two reasons, both practical. One: squaring kills the sign, so a +4 mistake and a −4 mistake both count as bad (without it they'd cancel out and a terrible model could show zero error). Two: squaring punishes big misses far more than small ones — being off by 10 costs 100, being off by 1 costs 1 — so the model prioritises fixing its worst mistakes.

Step 4 — backpropagation: where the gradient formula comes from

This is the part most tutorials skip. We want to know how the loss changes when w changes. The loss depends on w only through the prediction, so we chain two simple derivatives together:

Backpropagation in one picture: walk the arrows backwards, multiplying the local derivative at each hop. That's the chain rule, and it's all backprop is — even in a 100-layer neural network.

Averaged over all the points, that gives the two gradients:

dw = mean( 2 × (ŷ − y) × x )
db = mean( 2 × (ŷ − y) × 1 )

db has no x in it because b is added on its own — nudging b shifts every prediction by the same amount, regardless of how big x is. Whereas dw is scaled by x: a point with a big x has more leverage over the slope, so it gets a bigger vote.

The loss curve's shape is typical: a cliff at the start (easy wins), then a long flat tail (fine-tuning). This is why people stop training early — the last 80 epochs barely change anything.

What sklearn actually does here. LinearRegression() doesn't use gradient descent at all — for a plain straight-line fit there's an exact algebraic formula (the "normal equation") that jumps straight to the answer in one shot. Gradient descent is what you need once the model is too complex for a closed-form solution. Learn it here, where it's simple, because it's the same machinery that trains everything bigger.
02

Logistic regression

Use it when the answer is a category, not a number — malignant/benign, spam/not-spam, pass/fail. Despite the name, it's a classifier.

The problem with using a straight line for yes/no

Your labels are 0 and 1. A straight line doesn't know that — feed it a big enough x and it happily predicts 3.7, or −1.2. Those aren't answers to a yes/no question. We need something that squashes any number into the range 0→1 so it can be read as a probability.

Step 1 — the model formula (two stages now)

z = w · x + b
p = sigmoid(z) = 1 / (1 + e−z)

Stage one is identical to linear regression — same weight, same bias, same straight-line calculation. Stage two is the only new idea: the sigmoid function bends that unbounded number into a probability. That's the whole difference between the two models.

What the sigmoid does to a few numbers

Note z = 0 → p = 0.5: that's the decision boundary. Positive z leans yes, negative leans no, and the further from zero the more confident. Sigmoid never quite reaches 0 or 1 — the model is never absolutely certain.

Step 2 — forward pass on three patients

Toy data: x = tumour size, y = 1 for malignant. Starting again from w = 0, b = 0:

patientxyz = w·x+bp = sigmoid(z)
A2.000×2.0+0 = 00.500benign, but model says coin-flip
B4.010×4.0+0 = 00.500malignant, model says coin-flip
C7.510×7.5+0 = 00.500malignant, model says coin-flip

Step 3 — the loss: log loss (cross-entropy), and why not MSE

loss = −mean( y·log(p) + (1−y)·log(1−p) )

It looks scarier than it is. Because y is always 0 or 1, one of the two halves always switches off:

If y = 1
loss = −log(p)

Predict 0.9 → small penalty (0.105). Predict 0.1 → huge penalty (2.303).

If y = 0
loss = −log(1−p)

Predict 0.1 → small penalty (0.105). Predict 0.9 → huge penalty (2.303).

The magic of the log is that it goes to infinity as you approach a confidently wrong answer. A model that says "99.9% malignant" about a benign tumour gets savaged. MSE would only give it a mild slap. Log loss punishes confident wrongness, which is exactly the behaviour you want from a medical classifier.

With every p = 0.5, our starting loss is −log(0.5) = 0.693 — the number you'll see at the top of every from-scratch logistic regression. It's the loss of knowing nothing.

Step 4 — backpropagation, and a very pleasant surprise

You'd expect chaining through a sigmoid and a log to produce a horrible formula. It doesn't. The two derivatives cancel almost perfectly, and you're left with:

dw = mean( (p − y) × x )
db = mean( (p − y) )

Compare that to linear regression's mean(2(ŷ−y)·x). Same shape. error × input, averaged. This is not a coincidence — it's why log loss is the "natural" partner for sigmoid, and the same pattern reappears in softmax classifiers and neural network output layers.

Plugging in our three patients

patienterror = p − yerror × x
A0.5 − 0 = +0.500+0.5 × 2.0 = +1.00too high → vote to lower w
B0.5 − 1 = −0.500−0.5 × 4.0 = −2.00too low → vote to raise w
C0.5 − 1 = −0.500−0.5 × 7.5 = −3.75too low → strong vote to raise w

Patient C's vote is nearly four times louder than A's, purely because their x is larger. Across the full 16-point toy set the averages come out to dw = −0.884 and db = 0.000 (the bias gradient is exactly zero here only because the set happens to be 8 benign and 8 malignant — the up-votes and down-votes cancel).

Reading the max_iter=5000 in your code. Sklearn uses a smarter optimiser called lbfgs rather than the plain fixed steps shown here, but it's solving the identical problem. max_iter caps how many steps it may take before giving up. If you see a ConvergenceWarning, it hit the cap before settling — raise it, or scale your features so the optimiser has an easier landscape to walk.

.predict() applies a 0.5 cut-off. .predict_proba() hands you the raw probability, which matters when the two errors aren't equally bad — missing a malignant tumour is far worse than a false alarm, so in practice you might classify as malignant at anything above 0.3.

03

Decision trees

Here the loop from section 00 does not apply. There are no weights, no gradients, no learning rate, and no epochs. A tree is built once, greedily, by repeatedly asking: what single yes/no question splits this pile of data most cleanly?

The measure of "messy": gini impurity

gini = 1 − (p0² + p1²)

where p₀ and p₁ are the fractions of each class in a group. Read it as: the chance that two items picked at random from this group disagree.

all benign0.000
7 / 3 split0.420
50 / 500.500

0.0 is a perfectly pure group (job done, stop splitting). 0.5 is maximum chaos for two classes. The tree's entire strategy is: make the impurity drop as much as possible with each question.

Choosing the very first split, by brute force

Ten patients, one feature (cell size 1–10). Labels: sizes 1–4 benign, 5 malignant, 6 benign, 7–10 malignant. Root gini = 0.500. The tree tries every candidate threshold and scores each one:

thresholdleft groupgini Lright groupgini Rweighted
size < 2.5n = 20.000n = 80.4690.375meh
size < 4.5n = 40.000n = 60.2780.167best
size < 5.5n = 50.320n = 50.3200.320poor
size < 6.5n = 60.278n = 40.0000.167tied best
size < 7.5n = 70.408n = 30.0000.286poor

The weighted column is the average of the two child ginis, weighted by group size — a pure group of 2 counts less than a pure group of 8. The winner drops impurity from 0.500 to 0.167. That question becomes the root node, and then the process repeats independently inside each child.

With 30 features, as in breast_cancer, sklearn does this for every threshold of every feature at every node. That's all "training" a tree means — an exhaustive search, no calculus involved.

What max_depth actually limits

Depth counts layers of questions. Each extra layer can double the number of leaves, so the regions the tree carves get exponentially smaller.

Why unlimited depth memorises

Left unrestricted, the tree keeps splitting until every leaf is pure — which, in the worst case, means one training patient per leaf. At that point it can recite the training set perfectly and has learned nothing generalisable. Your own numbers show it exactly:

train scoretest score

Real output from load_breast_cancer with random_state=42.

The diagnostic to internalise: it's not the train score that tells you about overfitting, and it's not the test score alone either — it's the gap between them, and whether the test score is still improving. Here test stopped improving after depth 3 while train kept climbing. Everything past depth 3 is pure memorisation with zero payoff.

The mistake worth remembering. Running this loop on load_diabetes gives test = 0.0 at every depth. That's not overfitting — it's the wrong tool. The diabetes target is a continuous number, so DecisionTreeClassifier treats every distinct value as its own class and can essentially never hit one exactly. Continuous target → use a Regressor. Category target → use a Classifier.

04

Cross-validation

Everything above was scored on a single train/test split. That's one experiment, and one experiment can be lucky. Cross-validation runs several and shows you the spread.

The problem, concretely

train_test_split shuffles once and cuts once. If the 20% that landed in your test set happened to contain the easy cases, your score flatters the model. If it caught the awkward ones, the score is unfairly harsh. You have no way to tell which happened — because you only have one number.

k-fold: reuse every row as test data exactly once

held out for testing this roundused for training this round

With cv=5: cut the data into 5 equal slices, then run 5 completely separate experiments. Each round trains a fresh model on 4 slices and tests on the 1 left out. Nothing carries over between rounds — round 3's model knows nothing about round 2.

The payoff: every single row gets to be test data exactly once, and training data four times. You use 100% of your data for evaluation instead of 20%.

Reading the three numbers

# real output for LogisticRegression on breast_cancer
scores       = [0.939, 0.947, 0.982, 0.930, 0.956]

scores.std()  = 0.018
mean — your headline number
0.951

0.018

Five folds, one dashed mean. Tight clustering = a stable model.

mean is the estimate you quote and the one you use to compare models. std is the part people ignore and shouldn't — it's your error bar. Here 0.018 is small, so the folds agree and the 0.951 is trustworthy. A std of 0.15 would mean performance swings wildly depending on which patients you happen to test on, and any single train/test score would be close to meaningless.

Comparing two models honestly. Model A at 0.95 ± 0.01 genuinely beats model B at 0.93 ± 0.01. But model A at 0.95 ± 0.08 vs B at 0.93 ± 0.08? Those overlap completely — you cannot claim A is better. This is precisely what the single-split workflow can never tell you.

Things that trip people up

questionanswer
Which model does it return?None. cross_val_score throws all 5 models away and returns only the scores. It's a measuring tool, not a training tool. Fit your final model separately on all the data afterwards.
Why pass raw X, y and not X_train?Because it does the splitting itself, five times. Handing it pre-split data just wastes the data you held back.
Does it shuffle?Not by default — it slices in the order the rows sit. If your data is sorted by class this is a disaster. Pass cv=KFold(5, shuffle=True, random_state=42) to be safe.
What score is it reporting?The model's default .score() — accuracy for classifiers, R² for regressors. Override with scoring='f1', 'roc_auc', etc.
Why 5?Convention balancing cost and reliability. 10 is also common. More folds = more training data per round, but k times the compute.
Isn't this k times slower?Yes, exactly k times. That's the price of the error bar.

Where it really pays off: choosing max_depth

# instead of eyeballing one split, score each depth 5 times
from sklearn.model_selection import cross_val_score
from sklearn.tree import DecisionTreeClassifier

for depth in [1, 3, 5, None]:
    m = DecisionTreeClassifier(max_depth=depth, random_state=42)
    s = cross_val_score(m, X, y, cv=5)
    print(depth, s.mean().round(3), s.std().round(3))

Now the depth you pick isn't hostage to one lucky split. This is the standard way to tune any setting — and when you want to search several settings at once, GridSearchCV is this exact loop with the bookkeeping done for you.

Which model when

First question: what kind of thing are you predicting?

Get this wrong and you get the diabetes-classifier disaster: a valid-looking script that scores 0.0 forever.

The reference table

*not covered here, but it's the natural sequel: many trees, each on a random subset, votes averaged. It fixes the memorisation problem almost for free.

A workflow that won't embarrass you

# 1. know your target before choosing anything
print(y[:10], len(set(y)))       # few unique values → classify

# 2. get an honest baseline with the error bar
scores = cross_val_score(model, X, y, cv=5)
print(scores.mean(), scores.std())

Six things worth memorising

01Training is always: guess → measure wrong → find the downhill direction → step. Only trees skip it.
02The gradient for both regressions collapses to the same shape: mean(error × input).
03Backprop is just the chain rule walked backwards through the forward pass.
04Overfitting shows as a widening gap with a flat test score — not as a high train score alone.
05A single train/test score has no error bar. Cross-validation gives you one; read the std.
06Match the tool to the target: continuous → Regressor, categorical → Classifier.
